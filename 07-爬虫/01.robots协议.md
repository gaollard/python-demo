# Robots 协议（robots.txt）

爬虫入门必看：网站用 `robots.txt` 告诉爬虫「哪些能爬、哪些别爬」。**不是法律强制锁**，而是行业约定；正规爬虫应遵守，搜索引擎（Google / Bing）会读它。

官方协议：https://www.robotstxt.org/  
Google 说明：https://developers.google.com/search/docs/crawling-indexing/robots/intro

## 是什么

站点根路径下的纯文本文件：

```
https://example.com/robots.txt
```

爬虫在抓站前先请求这个文件，按规则决定是否继续访问某些 URL。

| 概念 | 含义 |
|---|---|
| User-agent | 爬虫身份（如 `Googlebot`、`*` 表示所有） |
| Disallow | 禁止抓取的路径前缀 |
| Allow | 允许抓取的路径（覆盖更宽的 Disallow） |
| Sitemap | 站点地图 URL，方便搜索引擎发现页面 |
| Crawl-delay | 抓取间隔（秒），非标准，部分引擎支持 |

## 语法示例

```txt
# 对所有爬虫
User-agent: *
Disallow: /admin/
Disallow: /private/
Allow: /public/

# 只针对某爬虫
User-agent: Googlebot
Disallow: /nogoogle/

# 禁止整站
User-agent: *
Disallow: /

# 允许整站（等价于没有限制）
User-agent: *
Disallow:

Sitemap: https://example.com/sitemap.xml
```

规则要点：

1. **最长匹配优先**：路径匹配越具体越优先；同长度时 `Allow` / `Disallow` 看具体实现（Google 有明确规则）。
2. **按 User-agent 分组**：先找最匹配的 User-agent 块，再在该块内匹配路径。
3. **`*` 通配、`$` 结尾**：部分引擎支持，如 `Disallow: /*.pdf$`。
4. **空 `Disallow:`** 表示不禁止；`Disallow: /` 表示禁止全站。

## 为什么爬虫要先看它

```
开始爬站
   │
   ▼
GET /robots.txt
   │
   ├─ 不存在 / 解析失败 → 多数实现视为「无限制」（仍要守法与礼貌）
   ├─ Disallow 命中目标 URL → 跳过
   └─ 允许 → 再发业务请求（页面 / API）
```

不读 robots 就狂抓：容易被封 IP、违反站点服务条款，严重时可能涉及法律风险。学习/实验也建议先读再爬。

## Python 怎么读

标准库 `urllib.robotparser` 即可：

```python
from urllib.robotparser import RobotFileParser

rp = RobotFileParser()
rp.set_url("https://www.example.com/robots.txt")
rp.read()

ua = "MyBot/1.0"
url = "https://www.example.com/admin/secret"

print(rp.can_fetch(ua, url))   # False → 不该爬
print(rp.crawl_delay(ua))      # 若有 Crawl-delay，返回秒数，否则 None
```

批量检查：

```python
from urllib.robotparser import RobotFileParser

rp = RobotFileParser()
rp.set_url("https://www.python.org/robots.txt")
rp.read()

ua = "*"
candidates = [
    "https://www.python.org/",
    "https://www.python.org/dev/",
]

for u in candidates:
    print(u, "OK" if rp.can_fetch(ua, u) else "BLOCKED")
```

用 `requests` 自己拉文本也可以，但解析规则容易踩坑，优先用 `RobotFileParser`。

## 常见误区

| 误区 | 实际 |
|---|---|
| robots.txt 能挡住坏人 | 不能。任何人都可直接访问被 Disallow 的 URL；敏感内容不要只靠它 |
| 没有 robots.txt 就能随便爬 | 仍受版权、服务条款、反爬策略约束 |
| `Disallow: /` 网站就打不开 | 只约束遵守协议的爬虫，浏览器用户不受影响 |
| 写了 Allow 就一定被收录 | 只是「允许爬」；是否收录还看质量、链接等 |

## 写自己站点的 robots.txt

放在 Web 根目录，保证 `https://你的域名/robots.txt` 能 200 访问。

最小可用：

```txt
User-agent: *
Disallow: /api/internal/
Disallow: /admin/

Sitemap: https://你的域名/sitemap.xml
```

开发环境可临时全禁搜索引擎：

```txt
User-agent: *
Disallow: /
```

上线前改回正式规则，避免正式页被误伤。

## 和爬虫礼貌（Politeness）

即使 robots 允许，也建议：

1. 控制并发与频率（如 1 req/s 起，观察响应再调）。
2. 设置明确的 `User-Agent`（含联系方式更佳）。
3. 尊重 `Crawl-delay`、`Retry-After`、429/503。
4. 缓存 robots.txt（协议建议有有效期；实现里不要每个 URL 都重新拉）。

## 快速自检清单

- [ ] 目标站 ` /robots.txt` 是否存在、内容是否可读
- [ ] 你的 User-Agent 落在哪一组规则
- [ ] 目标路径是否被 `Disallow` / 被更具体的 `Allow` 放开
- [ ] 是否设置合理间隔，避免把站点打挂
- [ ] 敏感/登录态数据是否另有授权，而不是「robots 没写就不算」
