# FastAPI 目录结构最佳实践

项目结构没有唯一标准，核心原则是：**按职责拆分、按规模演进、保持可导入的 Python 包**。下面从最小项目到生产级布局，说明常见做法与注意事项。

参考官方文档：[Bigger Applications - Multiple Files](https://fastapi.tiangolo.com/tutorial/bigger-applications/)

---

## 1. 从最小到规范：按规模演进

| 阶段 | 适用场景 | 结构建议 |
|------|----------|----------|
| 原型 / 学习 | 几个接口、快速验证 | 单文件 `main.py` |
| 小型 API | 多资源、需要分组 | `app/` + `routers/` |
| 中型业务 | 有 DB、校验、业务逻辑 | 增加 `schemas/`、`models/`、`services/`、`dependencies/` |
| 生产级 | 多环境、测试、部署 | 补齐 `tests/`、配置、`.env`、依赖锁定 |

不要一上来搭完整脚手架；结构应随复杂度增长，而不是提前过度设计。

---

## 2. 官方推荐的多文件结构（起步版）

官方 Bigger Applications 示例大致如下：

```text
.
├── app/
│   ├── __init__.py
│   ├── main.py              # FastAPI 应用入口，挂载路由
│   ├── dependencies.py      # 共享依赖（鉴权、DB session 等）
│   ├── routers/
│   │   ├── __init__.py
│   │   ├── items.py         # 资源路由：APIRouter
│   │   └── users.py
│   └── internal/
│       ├── __init__.py
│       └── admin.py         # 内部/管理接口（可选）
```

要点：

- 每个目录都要有 `__init__.py`，才能作为 Python package 互相导入（例如 `from app.routers import items`）。
- 用 `APIRouter` 拆分路由，在 `main.py` 里 `include_router` 汇总。
- `dependencies.py` 放跨路由复用的依赖，而不是塞进某个 router。

启动方式（在项目根目录）：

```shell
fastapi dev app/main.py
# 或
uvicorn app.main:app --reload
```

## 3. 中型项目推荐结构（业务分层）

当接口变多、有数据库和真实业务时，建议把「路由 / 数据校验 / ORM / 业务逻辑」拆开：

```text
my_fastapi_project/
├── app/
│   ├── __init__.py
│   ├── main.py                 # 创建 app、注册路由、中间件、异常处理
│   ├── config.py               # 配置（可用 pydantic-settings）
│   ├── database.py             # 引擎、Session、Base
│   ├── dependencies.py         # 或 dependencies/ 包：get_db、get_current_user
│   ├── routers/                # 仅负责 HTTP：参数、状态码、调用 service
│   │   ├── __init__.py
│   │   ├── users.py
│   │   └── items.py
│   ├── schemas/                # Pydantic：请求体 / 响应体
│   │   ├── __init__.py
│   │   ├── user.py
│   │   └── item.py
│   ├── models/                 # SQLAlchemy 等 ORM 模型
│   │   ├── __init__.py
│   │   ├── user.py
│   │   └── item.py
│   ├── services/               # 业务逻辑，不直接依赖 Request/Response
│   │   ├── __init__.py
│   │   ├── user_service.py
│   │   └── item_service.py
│   └── core/                   # 可选：安全、日志、常量
│       ├── __init__.py
│       └── security.py
├── tests/
│   ├── __init__.py
│   ├── conftest.py
│   ├── test_users.py
│   └── test_items.py
├── .env                        # 本地密钥，勿提交
├── .env.example                # 环境变量模板，可提交
├── requirements.txt            # 或 pyproject.toml（poetry / uv）
├── .gitignore
└── README.md
```

### 各层职责

| 目录 / 文件 | 职责 | 不要做的事 |
|-------------|------|------------|
| `routers/` | 定义路径、状态码、依赖注入，调用 service | 写复杂业务、直接拼 SQL |
| `schemas/` | 定义入参/出参、校验与序列化 | 混入 ORM 模型（除非刻意用同一模型且边界清晰） |
| `models/` | 数据库表映射 | 处理 HTTP 细节 |
| `services/` | 用例/业务规则、事务编排 | 依赖 `Request` 对象、写路由装饰器 |
| `dependencies/` | `Depends` 可注入的共享能力 | 塞进大量无关业务代码 |
| `config.py` | 环境配置、开关 | 硬编码密钥到源码 |

调用方向建议保持单向：

```text
routers → services → models / 外部 API
           ↑
       schemas（边界校验）
           ↑
     dependencies（注入 db / user）
```

## 4. 关键文件示例

### `app/main.py`：汇总路由

```python
from fastapi import FastAPI

from app.routers import items, users

app = FastAPI(title="My API")

app.include_router(users.router, prefix="/api/v1", tags=["users"])
app.include_router(items.router, prefix="/api/v1", tags=["items"])


@app.get("/health")
def health():
    return {"status": "ok"}
```

### `app/routers/users.py`：APIRouter 拆分

```python
from fastapi import APIRouter, Depends

from app.schemas.user import UserCreate, UserRead
from app.services import user_service

router = APIRouter()


@router.post("/users", response_model=UserRead)
def create_user(payload: UserCreate):
    return user_service.create_user(payload)


@router.get("/users/{user_id}", response_model=UserRead)
def get_user(user_id: int):
    return user_service.get_user(user_id)
```

### `app/schemas/user.py`：请求 / 响应模型分离

```python
from pydantic import BaseModel, EmailStr


class UserCreate(BaseModel):
    email: EmailStr
    name: str


class UserRead(BaseModel):
    id: int
    email: EmailStr
    name: str

    model_config = {"from_attributes": True}  # 便于从 ORM 对象序列化
```

### `app/dependencies.py`：共享依赖

```python
from collections.abc import Generator

from fastapi import Depends, Header, HTTPException


def get_token_header(x_token: str = Header(...)) -> str:
    if x_token != "fake-super-secret-token":
        raise HTTPException(status_code=400, detail="X-Token header invalid")
    return x_token
```

路由里通过 `Depends(get_token_header)` 复用即可；也可在 `include_router(..., dependencies=[Depends(...)])` 上挂整组路由级依赖。

## 5. 实践建议

### 包与导入

- 项目根作为工作目录，用绝对包导入：`from app.routers import users`，避免混乱的相对导入链。
- 入口是 `app.main:app`，不要把业务代码散落在仓库根目录（除 `tests/`、配置文件外）。

### 路由组织

- 按**业务资源**拆文件（`users.py`、`orders.py`），而不是按 HTTP 方法拆。
- 公共 `prefix`、`tags`、`dependencies` 尽量在 `include_router` 或 `APIRouter(...)` 上统一设置。
- 管理端 / 内部接口可放到 `internal/`，与对外 API 隔离。

### Schema 与 Model

- **对外契约用 schemas，持久化用 models**，两者分开更清晰，也便于 API 演进而不绑死表结构。
- Create / Update / Read 常用不同 schema，避免把密码哈希等字段暴露到响应里。

### 配置与密钥

- 用环境变量 + `pydantic-settings` 管理配置。
- `.env` 加入 `.gitignore`；提交 `.env.example` 说明所需变量。

### 测试

- `tests/` 镜像业务模块命名（`test_users.py`）。
- 对 router 用 `TestClient` / `httpx.AsyncClient`；对 service 可单独单测，减少全链路依赖。

### 依赖管理

- 小项目：`requirements.txt`（建议再加 `requirements-dev.txt`）。
- 中大型：`uv` 或 `poetry` + 锁文件，保证可复现安装。

## 6. 常见反模式

1. **单文件无限膨胀**：所有路由、模型、业务堆在 `main.py`。
2. **Router 里写业务**：难以复用、难测、难换数据源。
3. **Schema / Model 混用且边界不清**：接口字段与表字段强耦合，改库就破 API。
4. **缺少 `__init__.py` 或从错误 cwd 启动**：导致 `ModuleNotFoundError: No module named 'app'`。
5. **过早微服务 / 过深目录**：三个接口也拆十层 package，增加导航成本。

## 7. 与本仓库 `fastapi-demo` 的关系

当前 demo 仍是最小形态：根目录 `main.py`。适合对照 [01-介绍](./01-介绍.md) 快速跑通。

当你要加第二个资源、数据库或认证时，可按本文「官方起步版 → 业务分层版」迁移：

1. 创建 `app/` 包，把 `main.py` 移入。
2. 抽出 `routers/`。
3. 再按需增加 `schemas/`、`models/`、`services/`。

官方全栈模板（含前端、DB、Docker 等）见：[Full Stack FastAPI Template](https://github.com/fastapi/full-stack-fastapi-template)。本地学习时不必一上来用全量模板，按需取结构即可。
