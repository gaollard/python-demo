# `@property` 的作用

把「方法」伪装成「属性」：外部仍用 `obj.xxx` 读写，内部却能做校验、计算、只读控制。常和 `_` / `__` 私有字段一起用，是封装的常用手段。

## 为什么需要它

直接暴露字段，外部可以随意改，没法拦非法值：

```python
class Person:
    def __init__(self, age):
        self.age = age

p = Person(20)
p.age = -1  # 不合理，但语法上完全允许
```

用普通 getter / setter 方法可以控制，但调用变啰嗦：

```python
p.get_age()
p.set_age(25)
```

`@property` 两者兼顾：**像属性一样用，像方法一样可控**。

```python
print(p.age)   # 读：实际调用 getter
p.age = 25     # 写：实际调用 setter
```

## 基本用法：只读属性

只写 `@property`，不写 setter → 外部**只能读，不能赋**：

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

c = Circle(5)
print(c.radius)  # 5
# c.radius = 10  # AttributeError: can't set attribute
```

适合：对外暴露的状态不该被外部直接改，只能通过类自己的方法改内部 `_radius`。

## 可读可写：`@xxx.setter`

需要「能改，但改之前要校验」时，再配 setter：

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self._age = age  # 真实数据放内部字段

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if not isinstance(value, int):
            raise TypeError("年龄必须是整数")
        if value < 0 or value > 150:
            raise ValueError("年龄不合理")
        self._age = value

p = Person("Alice", 20)
print(p.age)   # 20
p.age = 25     # OK，走 setter
# p.age = -1   # ValueError
# p.age = "二十"  # TypeError
```

注意三点：

1. setter 装饰器名字必须是 **`@属性名.setter`**，且函数名与 property 同名
2. 真实存储一般用 `_age` / `__age`，避免和 `age` 这个 property 递归打架
3. `__init__` 里若写 `self.age = age`，也会走 setter（可顺便做校验）

```python
class Person:
    def __init__(self, age):
        self.age = age  # 走 setter，非法初始值也会被拦住

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("年龄不能为负")
        self._age = value
```

## 删除属性：`@xxx.deleter`

较少用。定义后可用 `del obj.xxx`：

```python
class Person:
    def __init__(self, name):
        self._name = name

    @property
    def name(self):
        return self._name

    @name.deleter
    def name(self):
        print("名字被删除")
        del self._name

p = Person("Alice")
del p.name  # 打印：名字被删除
```

## 计算属性（派生值）

不一定对应某个「存好的字段」，可以每次按公式算：

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        return self.width * self.height

    @property
    def perimeter(self):
        return 2 * (self.width + self.height)

r = Rectangle(3, 4)
print(r.area)       # 12 —— 像属性，实际是计算
print(r.perimeter)  # 14
# r.area = 100      # AttributeError：没 setter，不能写
```

好处：外部不用关心「面积是存的还是算的」；内部改实现也不影响调用方写法。

## 和普通方法的对比

| 写法 | 调用方式 | 适合场景 |
|---|---|---|
| 普通方法 | `obj.get_age()` | 有副作用、参数多、动作型操作 |
| `@property` | `obj.age` | 读起来像「对象的一个特征」 |
| `@property` + setter | `obj.age = 20` | 赋值时要校验 / 同步其它状态 |

经验：若名字听起来像**名词**（年龄、面积、余额）→ 倾向 property；像**动词**（登录、保存、发送）→ 用普通方法。

## 完整小例子：银行账户

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance  # 走 setter

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("余额不能为负")
        self._balance = value

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("存款必须为正")
        self.balance += amount  # 仍走 setter

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("取款必须为正")
        if amount > self.balance:
            raise ValueError("余额不足")
        self.balance -= amount

acc = BankAccount("Bob", 1000)
print(acc.balance)   # 1000
acc.deposit(200)
acc.withdraw(100)
print(acc.balance)   # 1100
# acc.balance = -50  # ValueError
```

## 常见坑

**1. 属性名和内部字段同名，导致无限递归**

```python
@property
def age(self):
    return self.age  # 错！又调用了自己 → RecursionError
```

应写成 `return self._age`。

**2. 只写了 setter，忘了 `@property`**

必须先有 `@property` 定义的 getter，才能挂 `@age.setter`。

**3. 把耗时操作做成 property**

property 看起来像「取个字段」，调用方可能频繁访问。重计算、读文件、打网络请求更适合做成普通方法 `load_xxx()`，语义更诚实。

## 怎么选（承接私有属性）

| 需求 | 做法 |
|---|---|
| 外部只读，内部可改 | `@property`，不配 setter |
| 外部可写，但要校验 | `@property` + `@xxx.setter` |
| 由其它字段推导出来 | 计算属性（只读 property） |
| 纯粹存数据、无需规则 | 普通公开属性即可 |

## 小结

- `@property`：让方法用属性语法访问
- 常配合 `_name` / `__name` 藏真实数据
- `@xxx.setter` 做赋值校验；`@xxx.deleter` 处理 `del`
- 适合「特征 / 状态 / 派生值」；不适合复杂动作或昂贵操作
- 内部字段名不要和 property 同名，避免递归
