# 私有属性和公开属性

封装的核心之一：哪些数据对外可见、哪些只在类内部使用。Python **没有真正的访问控制关键字**（没有 `private` / `public`），靠**命名约定**和**名称改写（name mangling）**表达意图。

## 对比一览

| 写法 | 约定含义 | 外部能否直接访问 | 典型用途 |
|---|---|---|---|
| `self.name` | 公开属性 | 可以 | 正常对外暴露的数据 |
| `self._name` | 内部使用（受保护，约定） | 技术上可以，但不建议 | 「别乱碰」的内部实现 |
| `self.__name` | 私有（名称改写） | 不能用原名直接访问 | 尽量避免被外部/子类误用 |

## 公开属性

不加下划线前缀的属性，就是公开的，类内外都能读写：

```python
class Person:
    def __init__(self, name, age):
        self.name = name  # 公开
        self.age = age    # 公开

    def intro(self):
        print(f"{self.name}, {self.age} 岁")

p = Person("Alice", 20)
print(p.name)   # Alice —— 外部可直接读
p.age = 21      # 外部可直接改
p.intro()
```

简单场景完全够用；真正需要隐藏实现细节时，再考虑私有约定。

## 单下划线 `_name`（内部约定）

以**一个下划线**开头，表示「这是内部实现，外部请不要依赖」：

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self._balance = balance  # 约定：内部字段

    def deposit(self, amount):
        if amount > 0:
            self._balance += amount

    def get_balance(self):
        return self._balance

acc = BankAccount("Bob", 1000)
print(acc.get_balance())  # 1000 —— 推荐通过方法访问
print(acc._balance)       # 也能读到，但破坏封装约定
```

要点：

- **不是语法强制**，解释器不会阻止外部访问
- `from module import *` 时，以 `_` 开头的名字默认不会被导入
- 子类仍可正常使用 `self._balance`

## 双下划线 `__name`（名称改写）

以**两个下划线**开头、且**不以两个下划线结尾**的属性，Python 会做 **name mangling**：把 `__balance` 改写成 `_类名__balance`。

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance  # 实际存成 _BankAccount__balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def get_balance(self):
        return self.__balance

acc = BankAccount("Bob", 1000)
print(acc.get_balance())          # 1000
# print(acc.__balance)            # AttributeError：原名不存在
print(acc._BankAccount__balance)  # 1000 —— 改写后的名字仍可强行访问
print(acc.__dict__)               # 能看到真实属性名
```

名称改写的作用主要是：

1. **避免子类无意覆盖**父类的同名私有属性
2. 提醒调用方：这不是公开 API

```python
class Animal:
    def __init__(self):
        self.__type = "Animal"

    def show(self):
        print(self.__type)  # 访问的是 _Animal__type


class Dog(Animal):
    def __init__(self):
        super().__init__()
        self.__type = "Dog"  # 实际是 _Dog__type，不会覆盖父类的

d = Dog()
d.show()           # Animal —— 父类私有属性还在
print(d.__dict__)  # {'_Animal__type': 'Animal', '_Dog__type': 'Dog'}
```

注意：`__init__`、`__str__` 这类**前后都是双下划线**的魔法方法，**不会**被改写。

## 私有方法

方法和属性规则一样：

```python
class User:
    def __init__(self, password):
        self.__password = password

    def __encrypt(self, text):
        return f"encrypted({text})"

    def login(self, password):
        # 类内部可以用原名调用私有方法
        secret = self.__encrypt(password)
        return secret == self.__encrypt(self.__password)

u = User("secret")
print(u.login("secret"))   # True
# u.__encrypt("x")         # AttributeError
# u._User__encrypt("x")    # 技术上可行，但不该这么用
```

## 对外暴露：用方法或 `@property`

不想让外部直接改内部状态时，公开「读/写接口」，把真实数据藏起来：

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.__age = age

    @property
    def age(self):
        """对外只读（或可在 setter 里校验）"""
        return self.__age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("年龄不能为负")
        self.__age = value

p = Person("Alice", 20)
print(p.age)   # 20 —— 像访问属性，实际走 getter
p.age = 25     # 走 setter，可做校验
# p.age = -1   # ValueError
```

这样外部用起来仍是公开属性的写法，内部却能控制读写规则。

## 怎么选

| 场景 | 建议 |
|---|---|
| 正常业务字段，允许外部读写 | 公开属性 `name` |
| 实现细节，外部不该依赖 | `_name`（最常用约定） |
| 强烈避免被子类/外部误用同名 | `__name`（少用，别滥用） |
| 需要校验、只读、计算属性 | `@property` + 内部 `_` / `__` |

经验原则：

- Python 社区更常用 **`_单下划线`** 表达「内部」
- `__双下划线` 只在确实需要防子类覆盖时用
- 「私有」是约定，不是铁锁；`obj._Class__attr` 始终能绕过

## 小结

- Python 的公开 / 私有靠**命名约定**，不是语法权限
- `name`：公开；`_name`：内部约定；`__name`：名称改写为 `_类名__name`
- 类内部用原名访问私有成员；外部强行访问属于破坏封装
- 需要受控读写时，优先 `@property`，而不是到处暴露字段
