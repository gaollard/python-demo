# MRO（方法解析顺序）

多继承时，Python 要决定「同名方法 / 属性先找谁」。这个查找顺序就叫 **MRO**（Method Resolution Order）。`super()` 也按这条链往下走，不是「随便找某个父类」。

## 怎么查看

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print(D.__mro__)
# (<class '__main__.D'>, <class '__main__.B'>, <class '__main__.C'>,
#  <class '__main__.A'>, <class 'object'>)

print([cls.__name__ for cls in D.mro()])
# ['D', 'B', 'C', 'A', 'object']
```

`__mro__` 和 `mro()` 一样：从当前类开始，一路找到 `object`。属性查找、方法调用都按这个顺序。

## 为什么需要固定顺序

菱形继承（两个父类又有共同基类）时，如果不规定顺序，会不知道先走哪条路、共同基类会不会被访问两次：

```
      A
     / \
    B   C
     \ /
      D
```

Python 用 **C3 线性化** 算出一条唯一、稳定的链。上例结果是：

```text
D → B → C → A → object
```

要点（直觉版）：

1. 子类永远排在父类前面（`D` 在 `B`、`C` 前）
2. 写在左边的父类优先于右边（`class D(B, C)` → `B` 在 `C` 前）
3. 每个类在整条链里只出现一次（`A` 不会因为既是 `B` 的父类又是 `C` 的父类而被查两次）

## 和属性 / 方法查找的关系

```python
class A:
    def hello(self):
        print("A")

class B(A):
    def hello(self):
        print("B")

class C(A):
    pass

class D(B, C):
    pass

D().hello()          # B —— 按 MRO 第一个找到的是 B.hello
print(D.__mro__)     # D, B, C, A, object
```

找 `hello`：先看 `D`（没有）→ `B`（有）→ 停止。不会再去 `C`、`A`。

## 和 `super()` 的关系

`super()` **不是**「调用直接父类」，而是「按 MRO 找**下一个**还实现了该方法的类」。

```python
class A:
    def hello(self):
        print("A")

class B(A):
    def hello(self):
        print("B")
        super().hello()   # 下一个是 C，不是 A

class C(A):
    def hello(self):
        print("C")
        super().hello()   # 下一个是 A

class D(B, C):
    def hello(self):
        print("D")
        super().hello()   # 下一个是 B

D().hello()
# D
# B
# C
# A
```

MRO 是 `D → B → C → A → object`，所以 `super()` 沿着这条链依次执行，每个类只跑一次。这就是多继承里推荐用 `super()` 的原因。

单继承时：`super()` ≈ 父类，效果和「父类名.方法(self)」差不多；多继承时差别就大了。

## 多继承初始化的坑（和 MRO 强相关）

`super().__init__(...)` 也只调 MRO 里的**下一个** `__init__`，不会自动把所有父类都初始化一遍。

```python
class Father:
    def __init__(self, name):
        self.name = name

class Mother:
    def __init__(self, age):
        self.age = age

class Child(Father, Mother):
    def __init__(self, name, age):
        super().__init__(name)  # 只等价于 Father.__init__
        # Mother.__init__ 根本没执行 → 没有 self.age

print([c.__name__ for c in Child.__mro__])
# ['Child', 'Father', 'Mother', 'object']
```

若父类里也写了 `super().__init__(...)`，参数还会按位置传给下一个父类，容易出现「不报错但值错了」的静默 bug。

### 常见解法

**解法一：显式调每个父类**（简单场景）

```python
class Child(Father, Mother):
    def __init__(self, name, age):
        Father.__init__(self, name)
        Mother.__init__(self, age)
```

缺点：类名写死；若有共同基类，基类 `__init__` 可能被执行两次。

**解法二：协作式 `super()` + `**kwargs`（推荐）**

整条 MRO 上的类都用关键字参数，各自取走认识的参数，剩下的继续往后传：

```python
class Father:
    def __init__(self, name, **kwargs):
        self.name = name
        super().__init__(**kwargs)

class Mother:
    def __init__(self, age, **kwargs):
        self.age = age
        super().__init__(**kwargs)

class Child(Father, Mother):
    def __init__(self, **kwargs):
        super().__init__(**kwargs)

c = Child(name="Tom", age=18)
```

## 小结

| 概念 | 要点 |
|---|---|
| MRO | 多继承时查找方法的固定顺序，可用 `__mro__` / `mro()` 查看 |
| C3 | Python 用来算这条顺序的算法；左边父类优先，每类只出现一次 |
| `super()` | 按 MRO 找下一个类，不是固定「直接父类」 |
| `__init__` | `super().__init__` 只初始化链上下一个；多父类参数不一致时要显式调用或 `**kwargs` 协作 |

日常写代码：优先单继承；真要多继承时，先 `print(类.__mro__)` 看清顺序，再用 `super()` 协作，少写死父类名。
