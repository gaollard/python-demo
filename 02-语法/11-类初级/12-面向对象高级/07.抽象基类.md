# 抽象基类（ABC）

抽象基类（Abstract Base Class）定义「接口长什么样」，但自己不给完整实现，强制子类必须实现指定方法，否则不让实例化。

一句话：**用来规定「子类必须有哪些方法」，把约定从「口头 / 注释」变成「代码强制」。**

## 为什么需要它

在 `06.多态.md` 里我们用过一种土办法：父类方法里 `raise NotImplementedError`。

```python
class Animal:
    def speak(self):
        raise NotImplementedError("子类必须实现 speak")


class Bird(Animal):
    pass          # 忘了写 speak


b = Bird()        # 能创建，暂时不报错
b.speak()         # 跑到这里才炸 NotImplementedError
```

问题：**错误要等到真正调用时才暴露**。抽象基类能让错误提前到「创建对象」甚至「定义类」阶段。

## 基本用法：ABC + @abstractmethod

```python
from abc import ABC, abstractmethod


class Animal(ABC):                 # 继承 ABC，成为抽象基类
    @abstractmethod
    def speak(self):               # 抽象方法，只声明不实现
        """子类必须实现"""


class Dog(Animal):
    def speak(self):
        return "woof"


# Animal()            # TypeError: Can't instantiate abstract class Animal
# class Bird(Animal): pass
# Bird()              # TypeError: 没实现 speak，同样不能实例化

print(Dog().speak())  # woof —— 实现了抽象方法，正常使用
```

两个关键点：

- 类继承 `ABC`（或用元类 `metaclass=ABCMeta`）。
- 方法加 `@abstractmethod` 装饰器。

只要还有抽象方法没被实现，这个类就是「抽象的」，不能 `()` 实例化。

## ABC 到底拦在哪一步

| 情况 | 结果 |
|---|---|
| 直接 `Animal()` | 报错，抽象类不能实例化 |
| 子类没实现全部抽象方法，实例化子类 | 报错 |
| 子类实现了全部抽象方法 | 正常创建对象 |

注意：**定义 `class Bird(Animal): pass` 这一步不报错**，报错发生在 `Bird()` 实例化时。

## 抽象方法也可以有默认实现

`@abstractmethod` 不代表方法体必须为空。子类仍必须重写，但可以用 `super()` 复用父类逻辑：

```python
from abc import ABC, abstractmethod


class Animal(ABC):
    @abstractmethod
    def speak(self):
        print("(某种动物发出了声音)")   # 提供公共部分


class Dog(Animal):
    def speak(self):
        super().speak()               # 复用父类默认实现
        print("woof")


Dog().speak()
# (某种动物发出了声音)
# woof
```

## 抽象属性 / 抽象 property

配合 `@property` 一起用，可以强制子类提供某个属性：

```python
from abc import ABC, abstractmethod


class Shape(ABC):
    @property
    @abstractmethod
    def area(self):
        """子类必须提供 area"""


class Circle(Shape):
    def __init__(self, r):
        self.r = r

    @property
    def area(self):
        return 3.14 * self.r ** 2


print(Circle(2).area)   # 12.56
```

顺序要点：`@property` 在上，`@abstractmethod` 在下。

## 抽象基类 vs 鸭子类型，什么时候用

Python 日常更偏爱鸭子类型（见 `06.多态.md`）：不强制继承，有方法就能用。抽象基类是「需要硬约束」时才上的工具。

| 方案 | 检查时机 | 约束力 | 适用场景 |
|---|---|---|---|
| 鸭子类型 | 运行时调用才知道 | 弱，灵活 | 小脚本、快速开发、Python 主流写法 |
| `NotImplementedError` | 调用该方法时 | 中 | 简单提醒，不想引入 abc |
| 抽象基类 ABC | 实例化时 | 强 | 团队协作、框架插件点、公共库接口 |

选择原则：**优先鸭子类型保持简单；当「接口必须被遵守、忘写要立刻报错」时，再用 ABC。**

## 标准库里的抽象基类

Python 自带的 `collections.abc` 里有大量现成抽象基类，实现对应方法就能获得完整能力，也能用于 `isinstance` 判断：

```python
from collections.abc import Iterable

print(isinstance([1, 2], Iterable))   # True
print(isinstance(123, Iterable))      # False
```

常见的有 `Iterable`（要 `__iter__`）、`Sequence`、`Mapping` 等。这也是「抽象基类 + 鸭子类型」的结合：既能强制接口，又能配合 `isinstance` 做类型判断。

## 小结

| 要点 | 说明 |
|---|---|
| 定义 | 继承 `ABC`，方法加 `@abstractmethod` |
| 作用 | 强制子类实现接口，抽象类本身不能实例化 |
| 报错时机 | 实例化（不是定义类）时才报错 |
| 抽象 property | `@property` 在上、`@abstractmethod` 在下 |
| 何时用 | 需要硬约束接口时；否则优先鸭子类型 |

抽象基类是「把接口约定写成代码」的手段：对外声明必须实现什么，对内交给各子类去填不同实现——本质上仍是为多态服务。
